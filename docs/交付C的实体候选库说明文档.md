# 实体候选库交付说明文档

## 概述
本文档描述了B模块生成的实体候选库（entity_candidate.json）的格式、内容和使用方法，供C模块（构建V2版本知识图谱）使用。

## 文件格式
实体候选库以JSON格式存储，文件名为：`entity_candidate.json`

## 数据结构
每条实体记录包含以下字段：

| 字段名 | 类型 | 描述 | 示例 |
|--------|------|------|------|
| canonical_name | string | 标准实体名称 | "陕北剪纸" |
| aliases | array | 实体所有别名 | ["陕西民间剪纸", "陕北纸剪"] |
| category | string | 实体所属类别 | "传统美术" |
| region | string | 实体所属地区 | "陕西" |
| confidence | float | 置信分数（0-1） | 0.92 |
| source_documents | array | 来源文档ID列表 | ["ihchina_1a2b3c", "ihchina_4d5e6f"] |

## 使用说明

### 1. 实体抽取入库参考
C模块在构建知识图谱时，应使用本候选库作为实体归一的参考：
- 对于高置信度实体（confidence > 0.85），可以直接入库
- 对于低置信度实体（confidence ≤ 0.85），需要进行人工复核

### 2. 减少图谱重复节点
通过使用实体候选库，可以：
- 合并同义实体（如"陕北剪纸"和"陕西民间剪纸"）
- 区分重名实体（如"河北剪纸"和"陕北剪纸"）
- 减少知识图谱中的重复节点

### 3. 错误合并预防
候选库中的置信分数帮助识别可能的错误合并：
- 高置信度：实体归一可靠
- 中等置信度：需要人工确认
- 低置信度：可能存在错误，必须人工复核

### 4. 下游系统集成
C模块应实现以下逻辑：
```python
# 伪代码示例
for entity in entity_candidate:
    if entity.confidence > 0.85:
        # 直接入库
        graph.add_entity(entity.canonical_name, entity.category, entity.region)
    else:
        # 人工复核队列
        manual_review_queue.add(entity)
```

## 注意事项

1. **人工复核要求**：置信度低于0.85的实体必须由人工复核，不能直接入库
2. **动态更新**：实体候选库应定期更新，以反映新的实体发现
3. **错误处理**：如果发现候选库中的错误，请及时反馈给B模块进行修正
4. **版本控制**：使用版本号标记不同的候选库版本
